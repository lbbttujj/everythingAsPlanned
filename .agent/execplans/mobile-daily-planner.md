# Mobile-first умный ежедневник

## Purpose / Big Picture

Приложение развивается в умный ежедневник с тремя основными разделами: целями, расписанием недели и делами на сегодня. Пользователь задаёт направления, планирует и выполняет короткие дела, а в будущем получает AI-рефлексию о том, поддерживает ли его ежедневная активность личные цели. Переход по нижней навигации выглядит плавно и не создаёт лишнего визуального шума.

## Surprises & Discoveries

- Текущий `ActionItem` уже разделяет записи на `goal` и `act`, поэтому новая навигация не требует переноса ключа `planner.actions.v3` в `LocalStorage`.
- Поле выполнения отсутствует. Его можно добавить как необязательное `isCompleted`, поэтому ранее сохранённые записи останутся валидными.
- Локальный dev-сервер ответил `HTTP 200`, но встроенный браузер этого запуска не получил доступ к `localhost` по своей политике URL. Сборка и TypeScript-проверка прошли без ошибок.

## Outcomes & Retrospective

Реализован mobile-first фундамент умного ежедневника. «Сегодня» отображает дела на текущую дату как минималистичный список задач; задача отмечается круглым чекбоксом, а состояние сохраняется в `LocalStorage`. «Неделя» показывает понедельник–воскресенье вертикальными карточками; заголовок дня сворачивает или разворачивает его список, а кнопка `+` у дня открывает ту же однотекстовую форму и сохраняет дело на выбранную дату. «Бэклог» хранит идеи без срока в отдельных группах, которые также сворачиваются и меняют порядок drag-and-drop за левый grip. Новое дело добавляется без оценки, ценностей, процентов, описаний и последствий; уже сохранённые расширенные поля не удаляются. «Цели» открывает только долгосрочные цели с прежней анкетой, сортировкой, редактированием, удалением, ручным порядком и PDF-экспортом. Будущий AI-слой будет сопоставлять историю выполнения дел и личные цели, но не определять ценности за пользователя. Нижняя панель остаётся закреплённой, а контент вкладки появляется с коротким fade-and-slide переходом. Для людей с системной настройкой reduced motion анимация отключается.

Подтверждено командами `npm run typecheck` и `npm run build` 04.08.2026. `http://localhost:3000/` ответил `HTTP 200` после запуска `npm run dev`. Визуальная browser-проверка в этом запуске не завершилась, поскольку встроенный браузер заблокировал доступ к `localhost` политикой URL; это не ошибка приложения.

## Context and Orientation

`app/` содержит Next.js App Router и `app/globals.css`. `components/dashboard.tsx` владеет загрузкой и сохранением записей, модальными формами и сортировкой. `components/action-table.tsx` отображает таблицу и поддерживает редактирование, удаление, сортировку и drag-and-drop. `lib/types.ts` описывает `ActionItem`, в котором `goal` — долгосрочная цель, а `act` — конкретный поступок. `lib/action-storage.ts` хранит массив записей в `LocalStorage` по ключу `planner.actions.v3`.

## Idempotence and Recovery

Изменения не удаляют и не переименовывают ключ `planner.actions.v3`. Если новая реализация будет частично применена, старые записи остаются в `LocalStorage`; поле `isCompleted` необязательно и безопасно отсутствует. Повторный запуск `npm run typecheck` и `npm run build` не изменяет пользовательские данные. Восстановление старого интерфейса возможно отменой изменённых исходных файлов без очистки `LocalStorage`.

## Interfaces and Dependencies

- `ActionItem.isCompleted?: boolean` — флаг завершения бытового поступка; цели его не используют.
- `ActionItem.scheduledFor?: string` — локальная дата дела в формате `YYYY-MM-DD`; отсутствие даты означает «сегодня» для обратной совместимости.
- `TodayList` — клиентский компонент, принимающий `ActionItem[]`, `onToggleComplete`, `onEdit`, `onDelete` и `onAdd`.
- `ActionTable.sections?: "all" | "goals"` — ограничивает отображаемые секции, по умолчанию показывает все.
- `WeekCalendar` — клиентский компонент, принимающий дела и обработчики добавления на дату, отметки выполнения, редактирования и удаления.
- `BacklogGroup` и `BacklogNote` — отдельные модели групп и текстовых заметок без даты.
- `Dashboard` хранит `activeSection: "today" | "week" | "backlog" | "goals"` и продолжает использовать `loadActions` / `saveActions` вместе с `loadBacklog` / `saveBacklog`.
- Новые внешние зависимости не добавляются.
