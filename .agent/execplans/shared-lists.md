# Совместные списки по приглашению

## Purpose / Big Picture

Пользователь создаёт несколько общих списков внутри раздела «Бэклог», приглашает участников по e-mail и совместно ведёт простые текстовые пункты. Доступ выдаётся только после принятия приглашения и проверяется PostgreSQL Row Level Security, поэтому подмена запросов в браузере не открывает чужие данные.

## Surprises & Discoveries

- Текущие таблицы полностью персональные и используют прямое сравнение `auth.uid()` с `user_id`; совместный доступ нельзя безопасно добавить только клиентским фильтром.
- В нижней навигации уже четыре раздела, поэтому общие списки размещаются внутри «Бэклога» и не меняют основной navigation bar.
- Новые таблицы Supabase требуют явных `GRANT`, независимо от RLS.
- Supabase Security Advisor помечает публичные `SECURITY DEFINER` RPC, поэтому защищённая реализация вынесена в схему `private`, а публичные RPC оставлены `SECURITY INVOKER`-обёртками.
- RLS-политика выполняет helper от имени роли запроса: одного `USAGE` на `private` недостаточно, `authenticated` также требуется явный `EXECUTE` на оба helper. Это безопасно для Data API, пока схема `private` не входит в exposed schemas.

## Decision Log

- Decision: общие списки являются отдельной моделью, а личные группы бэклога не расшариваются.
  Rationale: сохраняет приватность и не требует рискованной миграции существующих данных.
  Date/Author: 2026-08-08 / пользователь и Codex.
- Decision: приглашения находятся только в приложении и привязываются к нормализованному e-mail из JWT.
  Rationale: приглашение может дождаться регистрации без service-role ключа или почтовой инфраструктуры.
  Date/Author: 2026-08-08 / пользователь и Codex.
- Decision: Realtime не используется; данные перечитываются при каждом входе в «Бэклог».
  Rationale: выбран простой и предсказуемый MVP.
  Date/Author: 2026-08-08 / пользователь и Codex.

## Outcomes & Retrospective

Миграции `20260808093153_shared_lists.sql`, `20260808094152_harden_shared_list_rpcs.sql` и `20260808095146_grant_shared_list_rls_helpers.sql` применены к linked-проекту. SQL smoke test с двумя существующими аккаунтами подтвердил создание списка, приглашение, атомарное принятие, совместные insert/update и каскадное удаление; транзакция завершена `rollback`, поэтому тестовых данных не осталось. После исправления grants отдельный запрос под ролью `authenticated` успешно прочитал все четыре таблицы через RLS. `npm run typecheck`, `npm run lint` и `npm run build` завершились успешно. Security Advisor не показывает замечаний по `shared_*`; Performance Advisor показывает только ожидаемые `INFO` о новых индексах, которые ещё не успели использоваться. Браузерная проверка на 1280px и 390px подтвердила загрузку приложения без error overlay, console errors и горизонтального переполнения. Полный UI-сценарий двух аккаунтов остаётся ручной приёмочной проверкой, так как в тестовом браузере не было пользовательской сессии.

## Validation and Acceptance

- Владелец создаёт список и приглашает адрес независимо от наличия аккаунта.
- Пользователь с совпадающим JWT e-mail видит pending-приглашение и принимает или отклоняет его.
- После принятия оба участника видят и изменяют пункты; после выхода или исключения доступ исчезает на уровне RLS.
- Только владелец переименовывает/удаляет список и управляет составом.
- Drag-and-drop работает мышью и touch; автор пункта отображается по данным участника.
- Личный бэклог и остальные разделы не меняют поведение.
- `npm run typecheck`, `npm run lint`, `npm run build` завершаются кодом 0; Supabase security/performance advisors не показывают новых проблем высокого приоритета.

## Idempotence and Recovery

Миграция добавляет новые таблицы и не меняет существующие данные. При сбое клиентские файлы можно откатить без потери личного бэклога. До появления production-данных миграцию можно удалить обратной миграцией с каскадным удалением только `shared_*`; после появления данных удаление требует экспорта. Повторные RPC-вызовы принятия и создания membership защищены primary key и проверкой статуса.

## Interfaces and Dependencies

- `SharedList`, `SharedListMember`, `SharedListInvitation`, `SharedListItem` — новые доменные типы.
- `loadSharedListsData()` — загружает списки, участников, пункты и приглашения текущего пользователя.
- RPC: `create_shared_list`, `invite_shared_list_member`, `respond_shared_list_invitation`, `cancel_shared_list_invitation`, `remove_shared_list_member`, `leave_shared_list`, `delete_shared_list`.
- Новые npm-зависимости не добавляются; используется существующий `@supabase/supabase-js`.
